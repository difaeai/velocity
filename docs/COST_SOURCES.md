# Cost sources — making the Cost of Velocity page fill itself in

The **Cost of Velocity** page (`/dashboard/costs`) works with nothing configured:
every amount is typed in from an invoice. This document is about the other mode,
where the three vendors that will report their own spend do it for you nightly.

Ten of the eighteen catalogue lines can be fetched. They are also the ten that
actually move month to month — the rest are fixed subscriptions and one-offs you
set once a year.

| Source | Fills in | Needs |
|---|---|---|
| **Google Cloud** | Firestore, Functions, Storage, App Hosting, phone-auth SMS, Maps, Gemini | A BigQuery billing export |
| **Anthropic** | Claude | An Admin API credential |
| **Meta** | WhatsApp conversations, ad spend | A WABA id (and an ad account id) |

Everything lands in one GitHub Actions secret, **`COST_SOURCES_ENV`**, as a block
of `KEY=value` lines. It is its own secret rather than an addition to an existing
block so it can be rotated without anyone having to reconstruct a set of
credentials they cannot read back out of GitHub.

```
BILLING_BQ_TABLE=velocity-fe379.billing_export.gcp_billing_export_v1_XXXXXX_XXXXXX_XXXXXX
ANTHROPIC_ADMIN_KEY=sk-ant-admin...
WHATSAPP_WABA_ID=1234567890
META_AD_ACCOUNT_ID=act_1234567890
```

Each line is optional and each source is independent. A missing credential means
that vendor reads **not connected** in the console and its lines stay
hand-entered — it is never an error, and it never breaks the page.

---

## 1. Google Cloud

**Google has no API that returns what you spent.** The Cloud Billing API covers
billing accounts and the *price catalogue*; actual cost only leaves Google
through the BigQuery billing export. So this is a two-part setup: switch the
export on, then let the functions read it.

### Enable the export

Cloud Console → **Billing** → **Billing export** → **BigQuery export** →
*Standard usage cost* → **Edit settings**, and pick (or create) a dataset.

> **Choose a US or EU multi-region dataset.** A multi-region dataset backfills
> from the start of the previous month. A **single-region dataset backfills
> nothing** — it only collects from the moment you enable it, and there is no way
> to fill in the gap afterwards. This decision is not reversible without losing
> history, so make it now even if you set up the rest later.

Detailed usage cost also works; standard is enough for per-service totals and is
cheaper to store.

### Let the backend read it

The scheduled function runs as the project's default compute service account —
usually `63950615894-compute@developer.gserviceaccount.com` (check the Cloud Run
service's identity if unsure). Grant it, on the project that owns the dataset:

- **BigQuery Job User** (`roles/bigquery.jobUser`) — to run a query at all
- **BigQuery Data Viewer** (`roles/bigquery.dataViewer`) on the dataset — to read
  the export table

### Set the table

`BILLING_BQ_TABLE` is the fully-qualified `project.dataset.table`. The table name
is generated by Google and carries your billing account id, e.g.
`gcp_billing_export_v1_012345_6789AB_CDEF01`. Copy it from the dataset rather
than typing it.

The value is interpolated into SQL — BigQuery has no parameter form for a table
identifier — so it is validated against a strict identifier pattern in
`backend/functions/src/costs/config.ts`. A value that does not match is treated
as *not configured* rather than being sent to BigQuery.

### How the numbers are attributed

Spend is grouped by Cloud service and mapped onto catalogue lines, **net of
credits** — credits are the free tier, and gross cost is a number nobody pays.

Two attributions are genuinely ambiguous and worth knowing:

- **2nd-gen Cloud Functions bill as Cloud Run.** A line reading *Cloud Run
  Functions* goes to Functions; a plain *Cloud Run* line goes to App Hosting,
  because that is what App Hosting is made of.
- **App Hosting is not one SKU** — it bills through Cloud Run, Cloud Build and
  Artifact Registry, and all three land on that line.

Anything unrecognised goes to **Google Firebase → Everything else on the Cloud
bill** rather than being dropped, so the fetched total always adds up to the real
bill even where the attribution is imperfect. The console names those services
under the Google Cloud source so you can see what landed there.

## 2. Anthropic

The organization cost report is an **admin** surface. The `ANTHROPIC_API_KEY` the
social desk writes with cannot read it, and should not be reused here anyway — a
credential that can see the org's billing is a bigger credential than one that
can send a message, and the two rotate on different schedules.

Create an Admin API key in the Anthropic Console (an organization owner has to do
it) and put it in `ANTHROPIC_ADMIN_KEY`. Both credential forms Anthropic issues
are accepted: keys beginning `sk-ant-` are sent as `x-api-key`, anything else as
`Authorization: Bearer`.

> The API returns **cents**, not dollars — `"123.45"` means \$1.23. The division
> lives in `sources.ts` and is commented, because getting it wrong is a
> hundred-fold error that would look entirely plausible on the dashboard.

## 3. Meta

One token covers both WhatsApp conversation cost and ad spend, and it falls back
to `WHATSAPP_TOKEN` when `META_COST_TOKEN` is unset — the system-user token that
already sends the driver alerts usually carries
`whatsapp_business_management` too. Set `META_COST_TOKEN` only if you want a
separate, narrower one.

- `WHATSAPP_WABA_ID` — the WhatsApp Business Account id (Business Manager →
  WhatsApp Accounts). Not the phone number id.
- `META_AD_ACCOUNT_ID` — optional, and only worth setting once you are actually
  running ads. With or without the `act_` prefix.

> **If your WABA bills through a Solution Partner's credit line, Meta returns no
> cost at all** — that is documented behaviour, not a misconfiguration. The
> console shows it as an error with that explanation, and only the partner can
> tell you those charges. Leave the WhatsApp line hand-entered in that case.

## What is never fetched

Meta Verified (the Instagram blue tick), the X API tier, the domain renewal,
Google Workspace, the Play developer fee, and PayFast's netted transaction fees.
None of these expose spend through an API, and all of them are fixed amounts you
confirm once and leave alone. FCM and EAS Build are free at Velocity's volume, so
they are always zero.

## Fetched vs typed

A fetched figure wins over a typed one, because it *is* the invoice and the typed
one is somebody's memory of an invoice — **but only until you pin the line.**
"Type my own" on any row pins it; the row keeps whatever you enter, and a
"Use the fetched number" link puts it back on automatic.

The two writers never share a field. The console writes `usdToPkr`, `overrides`
and `custom`; the refresh job writes `fetched`, `fetchedAt`, `fetchWindow` and
`fetchStatus`. Both use `mergeFields`, so neither can clobber the other's half of
the document.

## When it runs

`refreshPlatformCosts` runs daily at 06:00 Asia/Karachi and always asks about the
**last complete calendar month** — that is what an invoice covers, and a figure
that nearly matches the bill is worse than one that matches it exactly and is up
to a month old. It runs daily rather than monthly because vendors close a month a
few days into the next one; the last run to land is the right one.

`adminRefreshPlatformCosts` is the same job on demand, behind the **Refresh now**
button. It is disabled while you have unsaved edits, since a refresh reloads the
page.

## Checking it works

The console's source strip is the diagnostic: each vendor shows *not connected*,
*N lines*, or an error with the vendor's own message. If a source reports an
error, the function logs carry the full detail:

```
gcloud functions logs read refreshPlatformCosts --region asia-south1 --limit 50
```
